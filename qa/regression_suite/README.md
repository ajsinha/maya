# QA

## `regression-suite`

The executable half of the QA pass, and the reason it is kept rather than run
once. Every scenario in here is a statement about a control, written against a
live instance, and most exist because something was once wrong.

    python -m qa.regression_suite.run             # the generated sections
    python -m qa.regression_suite.scenario_run    # the hand-written scenarios
    python -m qa.regression_suite.sweep           # properties, across every endpoint
    python -m qa.regression_suite.replay          # published cases, from their own steps
    python -m qa.regression_suite.refusals        # every mapped refusal code
    python -m qa.regression_suite.summary         # where the pass has got to
    python -m qa.regression_suite.findings --plan # what is open, grouped to be fixed

The directory is `regression_suite` with an underscore rather than a hyphen
because Python cannot import a package whose name is not an identifier, and
these are imported: each scenario module registers its cases against
`scenarios/common.py`. A hyphen would mean loading every file by path and
giving up the imports between them.

`tests/test_qa_scenarios.py` guards the suite from the ordinary test run — a
regression suite that can quietly stop running is worse than none, because it
reports a clean result for checks nobody performed.

## What lives where

| | |
|---|---|
| `regression_suite/scenarios/` | the hand-written cases, one module per area |
| `regression_suite/harness.py` | a live application, three clients, real role-holders |
| `qa/QA-CASES.md` | the published case list these answer |
| `qa/results/` | raw output, regenerated by the commands above |
