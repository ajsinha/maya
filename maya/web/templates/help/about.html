What is MAYA?

MAYA is the system of record for quantitative features, feature sets, models, and the warrants that license a model to be trained or run.

Definition, data, documentation, approval and evidence live in one place, so any number a model produced can be rebuilt exactly, years later, by someone who was not there. A version freezes how a number is produced; a pin freezes what it was. A warrant binds this model version, this data and these parameters into one auditable, transferable instrument — and, because it is live, it can be withdrawn on a Friday afternoon when the model is found to be wrong.

Built for model-risk, quantitative research and data teams in regulated firms, where "we think this is what we ran" is not an answer an examiner accepts.

Honest limits

Stated so nobody has to discover them.

  • Benchmarks ran on one shared workstation. SC-4, SC-5 and 100k-object search pass; SC-3, 200 users on one node, is not met reliably (one run of three passes).
  • Out of scope by decision: a dedicated benchmark host, so SC-3 stays unsettled; the live Claude API, so the challenger's Claude provider is verified against a stub only; and Windows and macOS, so only Linux is exercised.
  • Single sign-on is proven against one identity provider, Keycloak 26.4. SAML back-channel (SOAP) logout is not supported; OIDC logout works both ways.
  • Spreadsheet import lifts a deliberately narrow slice of Excel and refuses the rest by cell.
  • The strong sandbox tier is Linux-only; macOS would run at moderate, Windows at minimal.
  • Search is MAYA's own inverted index; PostgreSQL tsvector and SQLite FTS5 are not used.
  • Custody anchors are only as external as the storage you point them at, and a timestamp authority's signature is checked only when its CA certificate is configured.

Competitive landscape

Three families of product touch the problem MAYA addresses, and each is good at what it does. Model risk management platforms — SAS Model Risk Management, IBM OpenPages Model Risk Governance, ModelOp, ValidMind, Yields and others — hold the inventory, the tiering, the approvals, the independent challenge and the findings, but see the model through documents about it. ML platforms and model registries — MLflow, Databricks, Amazon SageMaker, Google Vertex AI, Azure Machine Learning — hold the artefact, its runs and its deployment, but have no representation of approved use, challenge or remediation. Feature stores — Feast, Tecton, Hopsworks — solve point-in-time correctness for the data and stop at the data.

The split is consistent: one family governs without seeing the artefact, the others see it without governing it. MAYA is a record that does both for the chain behind a number — the data as it stood, sealed; the mathematics, evaluable; the licence to fit and to run, granted in advance and refusable.

Where MAYA is different
  • It derives what others ask somebody to type: the input contract from the formula, a pin's identity from its contents, what a training row could have known from two clocks.
  • It refuses before the fact. A warrant is a licence, not a log entry, so an unapproved fit or an unlicensed run is stopped rather than recorded.
  • Its evidence leaves with a verifier. A bundle is checked on a machine with no MAYA on it.
Where MAYA loses
  • It has no materiality tiering and no findings register yet, which a model risk function uses daily.
  • It neither trains nor serves models, by design, so it sits beside an ML platform rather than replacing one.
  • It is one author's work, open source, and has not been deployed at a supervised institution; the established products have the customers, the integrations and the support.

The practical reading: MAYA is a complement. It licenses what an ML platform trains and serves, and supplies the evidence a model risk platform records.
