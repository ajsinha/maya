{% extends "help/_topic.html" %} {% from "help/_macros.html" import step, concept, tip, warn, example, fields, screen, cards %} {% block body %} {% call concept('A pull is an ingest, not a live view') %}

A feature whose source is sql runs one reviewed query against a database you already have and appends the rows to its bitemporal ingest log, exactly like an uploaded file. Each pull lands with a knowledge time — the source's own publication column when the definition names one, otherwise the moment of the pull. MAYA never reads the source live at resolution time: that would absorb upstream restatements silently, which is the one thing bitemporality exists to prevent.

{% endcall %} {{ cards([ ('shield-lock', 'Read-only, twice over', 'One SELECT (or WITH … SELECT) passes a text check, and the connection itself is opened read-only by the driver.'), ('key', 'No stored passwords', 'A connection names an environment variable; the password is read from it at the moment of use.'), ('file-earmark-check', 'Reviewed like code', 'The query is part of the feature definition, so it is versioned, diffed and approved with it.'), ]) }} {% call step(1, 'An administrator creates the connection') %}

Connections live under {{ screen('/admin/sources', 'Admin → Sources') }} and are managed by the admin role only. The URL may name a user but must never carry a password; SQLite and PostgreSQL are the supported source databases.

{% call example('On the server: the password lives in the environment', 'bash') %} export WAREHOUSE_PW='…' # read at the moment of each pull, never stored by MAYA python run_maya_web.py {% endcall %} {% call example('Create and test it from Python', 'python') %} import maya.sdk as maya my = maya.connect(base_url="http://localhost:8600", api_key="maya_…") my.sources.create_connection( "warehouse", "postgresql+psycopg://reader@db.internal:5432/markets", password_env="WAREHOUSE_PW", description="Read replica of the markets warehouse") print(my.sources.test_connection("warehouse")) # {'ok': True, 'dialect': 'postgresql'} {% endcall %} {% call warn('A password in the URL is refused') %}

postgresql://reader:secret@host/db is rejected with a message telling you to move the password into an environment variable and name it in password_env.

{% endcall %} {% endcall %} {% call step(2, 'The designer writes the query into the feature') %}

In the feature designer, set the source type to sql, name the connection, write the query, and declare its parameters. Values are bound, never interpolated.

{% call example('The source block of a feature definition', 'json') %} "source": { "type": "sql", "connection": "warehouse", "query": "SELECT d AS date, sym AS symbol, close, published_at FROM px WHERE d >= :start", "params": {"start": {"type": "date", "value": "2026-01-01"}}, "knowledge_time_column": "published_at" } {% endcall %} {{ fields([ ('connection', 'the administrator-managed connection name'), ('query', 'exactly one SELECT or WITH … SELECT statement; parameters as :name'), ('params', 'name → {"type": string | int | float | date | bool, "value": …}'), ('knowledge_time_column', 'optional: the column that says when each row was published'), ]) }} {% call warn('What the text check refuses') %}

A second statement (a ; inside the query), anything that does not start with SELECT or WITH, and words such as insert, update, delete, drop, create, copy, attach or pragma outside string literals. Even if something slipped past, the connection is opened read-only (SQLite mode=ro; PostgreSQL default_transaction_read_only with a five-minute statement timeout).

{% endcall %} {% endcall %} {% call step(3, 'Pull the rows') %}

Pulls run on demand: the Pull now button on the feature's ingest page, the API, or the SDK. The definition must validate first. Each pull records the connection and a SHA-256 of the query in the ingest note and in the audit log (feature.pulled).

{% call example('Pull from Python', 'python') %} row = my.features.pull("eq/prices") print(row["rows"], row["restatement"], row["note"]) # 1250 False pulled from connection 'warehouse' (query 3f9a1c0b2e77) {% endcall %} {% call example('Pull over REST', 'bash') %} curl -X POST http://localhost:8600/api/v1/features/eq/prices/pull \ -H "Authorization: Bearer $MAYA_API_KEY" -H "Content-Type: application/json" -d '{}' {% endcall %} {% call tip('Restatements are flagged, not hidden') %}

When a pull brings rows whose index overlaps rows already in the log, the ingest is marked a restatement. The old values stay; as_of_known still answers what you knew before.

{% endcall %} {% endcall %}

Python sources: a producer function in the sandbox

When the numbers are computed rather than stored — a business-day calendar, a scenario grid, a closed-form curve — the python source is the specification's escape hatch. The definition carries a function produce(params); each pull runs it in the sandbox and appends what it returns, exactly as a SQL pull does.

{{ cards([ ('shield-lock', 'Sandboxed', 'No network, no filesystem, capped CPU, memory, wall-clock and output. The tier it ran at is recorded on the ingest.'), ('check2-circle', 'Reviewed', 'The code is part of the definition: hashed, diffed and approved like a query. Imports are allowlisted; open, eval and dunders are refused.'), ('clock-history', 'Bitemporal', 'A changed result is a restatement: it appends, and as_of_known still answers what you knew before.'), ]) }} {% call example('A curve from parameters', 'json') %} "source": { "type": "python", "code": "import numpy as np\n\ndef produce(params):\n days = np.arange(params['days'])\n return {'date': [f'2026-01-{d + 1:02d}' for d in days], 'tenor': ['1Y'] * len(days), 'rate': (params['base'] + 0.001 * days).tolist()}", "params": {"days": {"type": "int", "value": 5}, "base": {"type": "float", "value": 0.02}} } {% endcall %} {{ fields([ ('returns', '{column: [values]}, a list of {column: value} records, or a pandas DataFrame; dates may be date objects or ISO strings'), ('imports', 'math, statistics, datetime, calendar, numpy, pandas and the rest of the artifact allowlist — nothing that reaches the network or the disk'), ('limits', 'sources.python.cpu_seconds, memory_mb, wall_seconds and max_output_mb in application.yaml'), ]) }} {% call warn('It computes; it cannot fetch') %}

A producer has no network and no files, by design. Data that lives elsewhere comes in through a sql connection or an upload, where it is reviewed as data rather than hidden in code.
