{% extends "help/_topic.html" %} {% from "help/_macros.html" import step, concept, tip, warn, example, fields, screen, cards %} {% block body %} {% call concept('Two clocks on every row') %}

Every row MAYA stores carries two times. The event time is what the value is about — the first index column, such as the trading day. The knowledge time is when MAYA could first have known it — stamped at ingest as _knowledge_time. Because a correction is a new row with a later knowledge time, never an overwrite, MAYA can answer both "what is the value?" and "what did we believe the value was on 31 March?".

{% endcall %} {{ cards([ ('calendar-event', 'Event time', 'The date the number describes. Declared as the first index column.'), ('clock-history', 'Knowledge time', 'When the number became known. Stamped by MAYA on every ingest.'), ('filter', 'as_of_known', 'A cut-off on knowledge time. Rows known later are simply not there.'), ]) }}

A worked example

A vendor publishes a close for 5 January on the evening of the 5th, then corrects it on the 9th. Both batches are ingested with their true knowledge times:

{% call example('What the log holds for AAA on 2026-01-05', 'text') %} event time close _knowledge_time ingest 2026-01-05 102.1 2026-01-05T18:00:00Z the evening file 2026-01-05 102.4 2026-01-09T09:00:00Z the vendor's correction (a restatement) {% endcall %} {{ fields([ ('as_of_known = 2026-01-06', '102.1 — the correction did not exist yet'), ('as_of_known = 2026-01-10', '102.4 — the latest row known by then wins'), ('as_of_known not given', 'resolves "now": 102.4'), ('as_of_known = 2026-01-04', 'no row for 5 January at all: nothing about it was known'), ]) }} {% call step(1, 'How resolution uses it') %}

Resolution always runs in the same order, so the result is reproducible:

  1. Knowledge-time cut: drop rows known after as_of_known.
  2. Latest knowledge per key: for each full index key, keep the row with the greatest remaining knowledge time.
  3. Grid: as_is, or a calendar crossed with every non-date key.
  4. Rules: fill gaps per attribute, per group, in event-time order.

The resolution plan shown under a preview states the cut it used, e.g. "knowledge-time cut at now".

{% endcall %} {% call step(2, 'Ask what you knew') %}

On a feature's Data tab, fill in as of known and preview. The same cut is available everywhere data leaves MAYA:

{% call example('Python SDK', 'python') %} import maya.sdk as maya my = maya.connect(base_url="http://localhost:8600", api_key="maya_…") then = my.features.preview("maya://feature/eq/prices@v1", as_of_known="2026-01-06T00:00:00Z") now = my.features.preview("maya://feature/eq/prices@v1") data = my.features.download("maya://feature/eq/prices@v1", format="csv", as_of_known="2026-01-06T00:00:00Z") open("prices_as_known_jan6.csv", "wb").write(data["data"]) {% endcall %} {% call example('Pin exactly what was known at month-end', 'bash') %} python -m maya.cli feature pin eq/prices --version 1 --name eom --as-of 2026-01-31 \ --as-of-known 2026-01-31T23:59:59Z {% endcall %} {% call tip('A pin records its cut') %}

If you pin without --as-of-known, MAYA uses the moment of pinning and records that it defaulted, so the pin's provenance always says which knowledge it froze. A download's manifest records its as_of_known too.

{% endcall %} {% endcall %} {% call step(3, 'Why it matters for models: leakage') %}

A model trained on a restated history learns from numbers nobody had at the time. A training warrant therefore issues a signed leakage certificate: it checks every training row and flags any whose knowledge time is later than its event date plus the allowed lag (leakage_lag_days, one day by default). The certificate's status is certified, certified_with_exceptions (every exception justified) or refused (an exception without a justification).

{% call warn('Non-causal rules are a second kind of leakage') %}

backward_fill, linear_interp and spline_interp fill a gap with values from its future. They are reported in the fill report and on the version, and a training warrant's certificate is refused unless the warrant sets allow_non_causal and gives a non_causal_justification.

{% endcall %} {% endcall %} {% call step(4, 'Load history honestly') %}

The knowledge time is only as good as what you give it. When you backfill, pass the real publication time per batch (--knowledge-time) or per row (source.knowledge_time_column); see Ingesting data.
