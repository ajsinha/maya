{% extends "help/_topic.html" %} {% from "help/_macros.html" import step, concept, tip, warn, example, fields, screen, cards %} {% block body %} {% call concept('What a training warrant is') %}

A training warrant binds one approved model version to one feature set reference — ideally a sealed pin — and records the terms of the training run: the split, the seed, the target, the input bindings, the holdout policy and an expiry. It is drawn up before anyone trains, it is checked when it is created, and it is the only way to download training data from MAYA. The parameters that training produces come back against it.

{% endcall %} {{ cards([ ('patch-check', 'Contract checked', 'Every model input must map to a numeric feature-set attribute, and the target must exist. Every miss is listed.'), ('shield-check', 'Leakage certified', 'A signed certificate proves no row uses a value MAYA could not have known by its event time.'), ('fingerprint', 'Checksum cycle', 'Every download is hashed and recorded; parameters must name the checksum they were trained on.'), ]) }} {% call step(1, 'Draw up the warrant') %}

Open {{ screen('/warrants/training/new', 'Warrants → Training warrant') }}, or call the SDK. The model must be an approved version; the feature set can be a version or a pin, but only a pin freezes the data, so prefer maya://featureset/ns/name#series/date.

{% call example('Create a training warrant', 'python') %} import maya.sdk as maya my = maya.connect(base_url="http://localhost:8600", api_key="maya_…") w = my.training.create( namespace="credit", name="pd-2026q1", model="maya://model/credit/pd_logit@v3", featureset="maya://featureset/credit/pd_panel#q1/2026-03-31", spec={ "target": "default_12m", "split": {"train": 0.7, "validation": 0.15, "test": 0.15}, "seed": 42, "holdout": "escrowed", # or "none" "bindings": {"ltv": "loan_to_value"}, # model input -> feature-set attribute "expiry_days": 365, "leakage_lag_days": 1, }) print(w["id"], w["state"]) # draft {% endcall %}

Creation fails with ContractMismatch if the feature set does not satisfy the model's input contract, naming each missing or non-numeric input. Anything you leave out of spec takes its default:

{{ fields([ ('split', 'train / validation / test fractions; must be ≥ 0 and sum to 1 (default 0.7 / 0.15 / 0.15)'), ('seed', 'the split is a hash of (seed, index key), so it reproduces anywhere (default 42)'), ('holdout', '"escrowed" keeps the test rows inside MAYA; "none" includes them in the download'), ('target', 'the attribute the model predicts; needed for holdout scoring'), ('bindings', 'model input name → feature-set attribute name, when they differ'), ('expiry_days', 'after this the warrant refuses downloads and uploads; clone it to continue (default 365)'), ('leakage_lag_days', 'how long after its event date a value may become known (default 1)'), ('allow_non_causal', 'must be true, with non_causal_justification, if the set uses a non-causal fill'), ('leakage_justification', 'a written reason that turns late-known rows into a certified exception'), ]) }} {% endcall %} {% call step(2, 'Read the leakage certificate') %}

At creation MAYA resolves the feature set and checks, row by row, that each value's knowledge time is no later than its event date plus leakage_lag_days. The certificate is signed with MAYA's Ed25519 key and carries one of three statuses:

{{ fields([ ('certified', 'no violations and no non-causal fills'), ('certified_with_exceptions', 'violations or non-causal fills exist, and each one carries a written justification'), ('refused', 'something is unjustified; the leakage_certified check blocks submit and approve'), ]) }} {% call tip('Refused is not a dead end') %}

Look at the examples in the certificate, fix the data or the lag, or supply a justification, then clone the warrant: my.training.clone(w["id"], leakage_justification="…"). The clone is a new draft linked to its origin.

{% endcall %} {% endcall %} {% call step(3, 'Submit and approve') %}

The default policy runs contract_valid and leakage_certified on submit, and adds no_open_blocking_comments and one model_manager approval on approve.

{% call example('Move it through review', 'python') %} my.training.transition(w["id"], "submit") # …a model manager, not you: my.training.transition(w["id"], "approve", rationale="Contract and certificate reviewed") {% endcall %} {% endcall %} {% call step(4, 'Download the data — the checksum cycle') %}

Downloading records a custody event holding the content hash of exactly what you received. With an escrowed holdout, the test rows are not in the file. The SDK recomputes the hash on arrival and refuses a table that does not match.

{% call example('Fetch training data', 'python') %} table, manifest = my.training_data(w["id"]) # a pyarrow Table, checksum verified print(manifest["rows"], manifest["checksum"], manifest["escrowed_holdout"]) df = table.to_pandas() # the _split column says train or validation {% endcall %} {% call example('The same from the command line', 'bash') %} python -m maya.cli warrant fetch --out train.parquet {% endcall %} {% endcall %} {% call step(5, 'Upload the parameters') %}

Train wherever you like, then upload the fitted values with the checksum you trained on. Values are checked against each parameter's declared bounds. If the checksum is one MAYA issued for this warrant the set is verified_data; otherwise it is flagged unverified_data.

{% call example('Upload a parameter set', 'python') %} ps = my.training.upload_parameters( w["id"], {"beta0": -3.1, "beta_ltv": 2.4}, metrics={"auc": 0.81}, data_checksum=manifest["checksum"], notes="L2, C=1.0") print(ps["verified_data"], ps["flag"]) # True None {% endcall %} {% call example('params.json for the CLI', 'json') %} {"values": {"beta0": -3.1, "beta_ltv": 2.4}, "metrics": {"auc": 0.81}, "data_checksum": "9f2c…", "notes": "L2, C=1.0"} {% endcall %} {% call example('Upload from the command line', 'bash') %} python -m maya.cli warrant upload-params params.json {% endcall %} {% call warn('Unverified data blocks approval') %}

The parameter set's approve transition runs data_verified_or_justified. An unverified_data set is approved only with a written justification, passed as justification on the transition — and that justification is audited.

{% endcall %} {% endcall %} {% call step(6, 'Score the escrowed holdout, then seal') %}

Blind scoring runs the model on the test rows inside MAYA and returns metrics, never rows. Every attempt is counted and shown on the warrant, so repeated peeking is visible.

{% call example('Score, approve the parameters, seal', 'python') %} print(my.training.score_holdout(w["id"], parameter_set_id=ps["id"])) # {'metrics': {'rmse': …, 'mae': …, 'rows': …}, 'attempt': 1, …} my.training.parameter_transition(ps["id"], "submit") # a model manager approves the parameter set, then: my.training.seal(w["id"]) {% endcall %}

Sealing needs an approved warrant, and — when the model has parameters — an approved parameter set. After sealing no more parameters can be uploaded; clone the warrant to train again.

{% endcall %}

Revocation

The model owner or an administrator can revoke a warrant with a written reason (my.training.revoke(id, reason=…)). Revocation cascades: every execution warrant drawn on it is revoked too, whether live, suspended or still in draft (unless it is already revoked), and its owner is notified.
