{% extends "help/_topic.html" %} {% from "help/_macros.html" import step, concept, tip, warn, example, fields, screen, cards %} {% block body %} {% call concept('One engine, policies as data') %}

Every governed object — feature versions, feature set versions, model versions, parameter sets, training warrants and execution warrants — moves through the same workflow engine. What each type may do is a policy: plain data, stored in the database, edited in the UI, validated as it is edited and activated by a second administrator. The rules of governance are governed too.

{% endcall %} {{ cards([ ('diagram-2', 'States and transitions', 'draft → in_review → approved → published → deprecated → retired, plus changes_requested and withdrawn.'), ('patch-check', 'Checks block by name', 'A transition lists checks; any that fails refuses the move and says which, and why.'), ('people', 'Separation of duties', 'You cannot approve what you created, submitted or last changed — at the namespace\'s strictness.'), ]) }} {% call step(1, 'The lifecycle every object shares') %} {{ fields([ ('submit', 'draft or changes_requested → in_review; mints the immutable version'), ('request_changes', 'in_review → changes_requested; back to the author'), ('approve', 'in_review → approved, once every required approval is in and every check passes'), ('withdraw', 'in_review → withdrawn, by the author'), ('publish', 'approved → published (feature, feature set and model versions)'), ('deprecate', 'approved or published → deprecated'), ('retire', 'the end of the road; administrators only'), ]) }}

Your queue at {{ screen('/workflow', 'Workflow → My queue') }} lists everything waiting for a decision you can make. Each review page shows the checks, the outstanding approvals, the history and the comments.

{% endcall %} {% call step(2, 'Read a policy') %}

This is the shipped policy for feature versions, as YAML. Each transition names where it may start (from), where it lands (to), the capability letter the actor needs, the checks that must pass and the approvals required.

{% call example('feature_version policy', 'yaml') %} states: [draft, in_review, changes_requested, approved, published, deprecated, retired, withdrawn] transitions: submit: {from: [draft, changes_requested], to: in_review, capability: U, checks: [definition_valid]} approve: from: [in_review] to: approved capability: A approvals: [{role: feature_manager, count: 1}] checks: [definition_valid, quality_passes, no_open_blocking_comments] retire: {from: [deprecated], to: retired, roles: [admin]} sla_days: {in_review: 5} notify: {in_review: [feature_manager], approved: [owner], changes_requested: [owner]} {% endcall %} {{ fields([ ('capability', 'one of C create, R read, U update, A approve, P pin/seal, G grant, Q request a pin'), ('roles', 'restrict a transition to named roles (retire is admin-only)'), ('checks', 'registered check names; see the list below'), ('approvals', '{role, count} requirements; "when": "prod" applies only in a production namespace'), ('sla_days', 'how long an item may wait in a state before it counts as overdue'), ('notify', 'who is told when an object lands in a state: a role, or owner'), ]) }} {% endcall %} {% call step(3, 'The checks') %} {{ fields([ ('definition_valid', 'the feature or feature set definition validates'), ('quality_passes', 'the quality contract passes on current data'), ('members_approved', 'every member of a feature set is approved'), ('formula_typechecks', 'the model\'s formula IR is valid and typechecks'), ('spec_document_complete', 'the specification document is complete'), ('code_artifact_validated', 'the uploaded code artifact passed its validation ladder'), ('spec_true_build', 'the spec PDF is a true build, not a watermarked draft (when required)'), ('composite_members_mature', 'a composite model\'s members are mature enough'), ('contract_valid', 'a training warrant\'s input contract is satisfied'), ('leakage_certified', 'its leakage certificate is certified'), ('parameters_within_bounds', 'every parameter lies within its declared bounds'), ('data_verified_or_justified', 'parameters were trained on data MAYA issued, or are justified'), ('parameters_approved', 'an execution warrant\'s parameter set is approved'), ('no_open_blocking_comments', 'no reviewer comment marked blocking is still open'), ]) }} {% call tip('A comment can block') %}

Reviewers can mark a comment as blocking. Approval then waits until it is resolved: my.workflow.comment(object_type, object_id, "Unit of ltv?", blocking=True).

{% endcall %} {% endcall %} {% call step(4, 'Change a policy safely') %}

Edit policies at {{ screen('/workflow/policies', 'Workflow → Policies') }}. A draft is refused at save time if it has an unknown or unreachable state, a check nobody registered, a role that does not exist, an approval no role could satisfy, or no route to approved. Saving also previews the impact: objects the new policy would strand or block.

{% call example('Draft, then have a second admin activate', 'python') %} import maya.sdk as maya my = maya.connect(base_url="http://localhost:8600", api_key="maya_…") text = my.workflow.policy_yaml(policy_id) # start from the active one print(my.workflow.validate_policy("feature_version", edited_policy)) draft = my.workflow.draft_policy("feature_version", edited_policy, scope="credit", note="two approvals in credit") # a different administrator: my.workflow.activate_policy(draft["id"]) {% endcall %}

A policy can be scoped to one namespace (scope="credit"); the engine uses the namespace's active policy first and falls back to the global one ("*"). The old version is kept as superseded, and export → import → export of the YAML is byte-identical.

{% endcall %} {% call step(5, 'Separation of duties') %}

Each namespace sets its strictness; the presets choose one for you.

{{ fields([ ('strict', 'you cannot approve if you created, submitted or last modified the object (preset: regulated)'), ('two_person', 'you cannot approve what you submitted (preset: standard)'), ('none', 'no restriction (preset: small_team, and every scratch namespace)'), ]) }} {% call warn('Self-approval is a dev-only escape hatch') %}

workflow.allow_self_approval in config/application.yaml is honoured only when app.environment is dev.

{% endcall %} {% endcall %} {% call step(6, 'Break-glass') %}

An administrator can force a transition past its checks and approvals — for an emergency, never quietly. It needs a written reason of at least ten characters, marks the object force_approved, notifies the owner with a BREAK-GLASS prefix, and appears on {{ screen('/workflow/break-glass', 'Workflow → Break-glass report') }} for review.

{% call example('Force an approval', 'python') %} my.features.transition("credit/ltv", 4, "approve", force=True, rationale="Regulator deadline today; review scheduled 2026-09-21") {% endcall %} {% endcall %} {% call step(7, 'The recorded challenger') %}

Every submission into review gets a challenge memo, written by a job and shown on the review page. It looks for look-ahead, unbounded fills, schema drift against the last approved version, thin or missing limitations, and a document that no longer matches its formula.
