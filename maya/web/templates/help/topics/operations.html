{% extends "help/_topic.html" %} {% from "help/_macros.html" import step, concept, tip, warn, example, fields, screen, cards %} {% block body %} {% call concept('One file, three overrides, no surprises at first use') %}

All configuration lives in config/application.yaml, a tracked file that carries no secret. Settings that change MAYA's behaviour — database dialect, environment, auth mode, sandbox tier — are validated at startup. A bad combination refuses to start, naming the key, rather than failing at first use.

{% endcall %} {{ cards([ ('file-earmark-text', 'application.yaml', 'The tracked defaults. A test keeps secrets out of it.'), ('file-earmark-lock', 'application.local.yaml', 'A git-ignored overlay beside it, for this machine and its secrets.'), ('terminal', 'Environment and flags', '${VAR:default} placeholders read the environment; --key=value on the command line wins over everything.'), ]) }} {% call step(1, 'Override a setting') %}

Precedence, lowest to highest: the YAML file, config/application.local.yaml, the environment, then command-line flags. Values like "${MAYA_PORT:8600}" read an environment variable with a default.

{% call example('Three ways to change the port', 'bash') %} MAYA_PORT=9000 python run_maya_web.py # the ${MAYA_PORT:8600} placeholder python run_maya_web.py --server.port=9000 # a flag, highest precedence # or: server.port in config/application.local.yaml {% endcall %}

{{ screen('/admin/config', 'Admin → Configuration') }} lists every effective setting and where it came from, with passwords, secrets and tokens redacted.

{% endcall %} {% call step(2, 'Pick the environment') %} {{ fields([ ('app.environment', 'dev | uat | prod (MAYA_ENV). Outside dev: no default admin password, a session secret must be set, the sandbox minimum tier is enforced'), ('app.secret_key', 'the session-signing secret (MAYA_SECRET_KEY). In dev, generated under storage.root/keys when unset'), ('storage.root', 'blobs, the Delta lake, keys, logs and the SQLite file (MAYA_HOME, default data)'), ('logging.format', 'text | json'), ]) }} {% call warn('Production refuses SQLite') %}

app.environment: prod with db.dialect: sqlite does not start. SQLite is for a single node and a small team: one writer at a time. For the same reason SQLite refuses several web processes: server.workers above 1 needs PostgreSQL, because the lock that keeps linking the audit chain and numbering versions atomic lives inside one process. See the operations guide.

{% endcall %} {% endcall %} {% call step(3, 'Switch SQLite and PostgreSQL') %}

Two schema files are generated from the same ORM metadata: maya/persistence/schema/sqlite.sql and postgresql.sql. One key chooses between them; nothing else changes.

{% call example('config/application.yaml', 'yaml') %} db: dialect: "${MAYA_DB_DIALECT:sqlite}" # sqlite | postgresql postgresql: host: "${MAYA_PG_HOST:localhost}" port: "${MAYA_PG_PORT:5432}" database: "${MAYA_PG_DATABASE:maya}" user: "${MAYA_PG_USER:maya}" password: "${MAYA_PG_PASSWORD:}" # environment or local overlay, never here {% endcall %} {% call example('Create the schema on a new PostgreSQL database', 'bash') %} export MAYA_DB_DIALECT=postgresql MAYA_PG_HOST=db.internal MAYA_PG_PASSWORD='…' python -m maya.cli admin init-db python run_maya_web.py {% endcall %} {% endcall %} {% call step(4, 'Upgrade without migrations') %}

MAYA has no migration framework. The hash of the schema is stamped into the database; if the code expects a different schema, MAYA refuses to start and prints these three commands. The same route moves an estate from SQLite to PostgreSQL. The export reads the database as it is, so it runs with the new version already installed; anything the new code no longer has is named in the bundle's manifest under not_carried, never dropped silently.

{% call example('Export, rebuild, import', 'bash') %} python -m maya.cli admin export-estate --out estate.mayabundle python -m maya.cli admin init-db --force python -m maya.cli admin import-estate --in estate.mayabundle {% endcall %} {% call tip('Check integrity afterwards') %}

python -m maya.cli admin verify-integrity re-hashes every pin and walks the audit chain. It exits non-zero on any drift or a broken chain, so it can gate a deployment script.

{% endcall %} {% endcall %} {% call step(5, 'The gates, run locally') %}

There is no hosted CI. The gate ladder runs on your machine: file size, import boundaries, seam imports, the single version source, no secrets in the tracked config, the table contract, colour contrast, SDK↔API parity, and schema drift.

{% call example('Run the gates', 'bash') %} git config core.hooksPath .githooks # once: the pre-commit hook runs the gates python tools/ci/gates.py # the fast static gates python tools/ci/gates.py --tests # …then the full test suite {% endcall %} {% call example('The whole suite against PostgreSQL', 'bash') %} MAYA_TEST_PG_URL=postgresql+psycopg://maya:…@localhost/maya_test python -m pytest -q {% endcall %} {% endcall %}
