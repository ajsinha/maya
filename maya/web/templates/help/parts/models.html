A model's mathematics is held as a formula IR: a typed expression tree of inputs, intermediate lets and one output. You never author it directly. You write the formula the way you already do, in LaTeX or plain text, or you upload a simple Python function, and MAYA derives the tree. The tree then earns its keep: it type-checks against a feature set, renders the specification's equations, produces a semantic diff between versions, generates reference code, and is the yardstick your implementation is tested against.

{% endcall %} {{ cards([ ('calculator', 'Formula', 'A closed-form model: LaTeX, text or lifted Python becomes the IR.'), ('box-seam', 'Black box or vendor', 'No closed form; a mandatory statement of what it estimates, and what cannot be verified.'), ('diagram-3', 'Composite', 'ensemble, pipeline, router, residual or hierarchical over other model versions.'), ]) }} {% call step(1, 'Write the mathematics in LaTeX') %}

Open {{ screen('/models/new', 'Models → New model') }} and paste the equations: lets first, the output last, one per line. Implicit multiplication, \frac, \sqrt, Greek letters, N(·) / \Phi for the normal CDF and e^{…} are understood. Anything the parser cannot read is refused with the position named, never guessed.

If you would rather see what MAYA makes of the notation before anything is created, open {{ screen('/models/kernel', 'Models → Design your compute kernel') }}. It runs the same parser and the same generator the registration path runs, and shows three things back: the mathematics rendered from the tree it parsed — not from your text, so a misreading is visible — the typed IR a version would store, and one self-contained Python function that computes it. It saves nothing; when the translation is right, one button carries the formula and the roles into the model designer.

Then say which free names are not features. Every name defaults to feature (supplied by the bound feature set); mark the rest:

A function whose body is assignments followed by one return can be lifted. Names read from params["…"] become parameters; names from X["…"] become features. math, numpy and scipy.stats.norm calls map onto IR operators. Loops, branches and unknown calls are refused with the line named.

{% call example('A liftable function', 'python') %} import numpy as np def predict(X, params): signal = X["momentum"] - X["reversal"] return params["beta"] * signal + params["alpha"] {% endcall %} {% call example('Create the model from it', 'python') %} my.models.create("quant", "tilt", python_source=open("tilt.py").read()) {% endcall %} {% endcall %} {% call step(3, 'Or lift it from an Excel workbook') %}

A large share of the models a bank actually runs are workbooks. On {{ screen('/models/new', 'Models → New model') }} choose Lift from an Excel workbook, or use the SDK or CLI. MAYA walks the formula graph back from one output cell: numeric cells it reaches become inputs, formula cells become lets, and defined names name them. The workbook itself is kept, by hash, and downloads from the model's Definition tab.

Command line: see Lifting from a spreadsheet in the full reference below.

{% call concept('Checked against the workbook itself') %}

Every time Excel recalculates it stores each formula's result in the file. MAYA evaluates the lifted formula at the workbook's own inputs and compares it with those results, cell by cell. Agreed: it reproduces them all. Disagreed: the cells are listed and submission is blocked. Unchecked: the file was never recalculated in Excel (for example, written by a script), so there was nothing to compare — say so, rather than assume agreement.

{% endcall %} {% call tip('Name your cells') %}

A defined name (rate, principal) becomes the input's name in the formula, the document and the diff. Unnamed cells are named by their address, such as B3, or Inputs_B3 when the model spans sheets. An empty cell reads as 0, as in Excel, and the report says which.

The model page shows the rendered equations, the input contract and the IR itself. The IR's operators are:

add sub mul div pow neg exp log sqrt abs ncdf npdf max min where gt lt ge le eq and or na (Excel's #N/A, from a spreadsheet lookup miss: evaluates to NaN)

The IR of yhat = a*x + b (roles a, b: parameter): see The IR document in the full reference below.

{% call tip('The hash ignores cosmetics') %}

The IR hash is taken over the canonical tree without its rendered latex, so reformatting an equation does not look like a change to the mathematics.

{% endcall %} {% endcall %} {% call step(5, 'Compare two versions semantically') %}

A reviewer is told what changed in the mathematics, such as an input added or a bound tightened, not shown a JSON diff.

A gradient-boosted tree or a vendor library has no formula to derive. Register it anyway: choose kind black_box or vendor. A black box must state, in prose, what it estimates and describe its architecture; a vendor model records the vendor's details and lists what cannot be verified rather than omitting it.

A declared black box: see Black boxes and vendor models in the full reference below.

{% call warn('A black box cannot be conformance-tested') %}

With no documented closed form there is nothing to compare an implementation against. MAYA says so in the conformance report instead of implying a check it did not perform.

Maturity

Every model version carries a maturity: experimental, candidate, approved, restricted, deprecated or retired. A composite can never claim more maturity than its least mature member.
