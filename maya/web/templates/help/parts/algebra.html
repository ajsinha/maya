A derived feature is not a copy of data and not a script. Its source is a derivation: an operator applied to other features. Every operator takes features and yields a feature definition, so results compose. Each operator has two halves: a typecheck that runs at submit time with no data at all (index compatibility, type unification, name clashes), and an execute that replays the operator over the resolved operands whenever the feature is read or pinned. Mistakes surface when you submit, not in a nightly job.

Choose Derived as the kind of definition in the {{ screen('/workbench/features/new', 'Workbench → Feature designer') }}, pick the operator, list the operands one per line, and give options as JSON. The same definition in JSON:

{% call example('Union of two vendors, preferring the first on collision', 'json') %} { "index": ["date", "symbol"], "index_types": {"date": "date", "symbol": "string"}, "schema": [{"name": "close", "type": "float64"}], "source": { "type": "derived", "derivation": { "operator": "union", "operands": ["maya://feature/eq/px_vendor_a@v2", "maya://feature/eq/px_vendor_b@v1"], "options": {"collision": "prefer_left"} } }, "resolution": {"grid": "as_is", "rules": {}}, "transform": [], "quality": [] } {% endcall %} {% call tip('Reference versions, not the moving head') %}

Operands name a version (@v2) or a pin. The derived feature's definition hash covers the operator, its canonical options and the operands, so a different operand is a different version. For commutative operators such as union the operand order does not change the hash.

If the typecheck fails, the submit is refused with the operator's own message, for example "compose attribute name clash ['close']; declare prefixes".

Rolling windows and other row-level steps

Windows, casts, filters and derived columns are transformation pipeline steps rather than operators. Use them inside a feature's transform list, or wrap another feature with the transform operator. Steps: rename, cast, filter, derive, aggregate, pivot, unpivot, window, lag, resample, dedupe, clip, winsorize.

A 20-day rolling mean over a derived feature: see Single-operand operators in the full reference below.

{% call warn('Look-ahead is refused, not warned about') %}

A negative lag reads the future and is rejected at submit. Resolution rules that look forward (such as a backward fill) mark the feature non-causal, and that flag travels through every derivation built on it, into feature sets and the leakage certificate of a training warrant.
