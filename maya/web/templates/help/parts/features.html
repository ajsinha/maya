{% from "help/_macros.html" import step, concept, tip, warn, example, fields, screen, cards %} {% call concept('A feature is a definition first, data second') %}

A feature is a governed recipe for a number: which rows identify it, what types its values have, where they come from, how gaps are filled, how the data is shaped, and what it must satisfy before anyone may rely on it. The data arrives separately (see Ingesting data) and is resolved through the definition every time it is read.

{% endcall %} {{ cards([ ('box-seam', 'From a source', 'csv, parquet, json, sql or delta: rows come from outside MAYA.'), ('diagram-3', 'Derived', 'An operator over other features: union, join, lag… type-checked at submit.'), ('layers', 'Extends a parent', 'Store only the diff over a parent version; pinned or tracking binding.'), ]) }}

Open {{ screen('/workbench/features/new', 'Workbench → Feature designer') }} and pick the kind of definition first; the form shows only the fields that kind needs.

{% call step(1, 'Index: what identifies a row') %}

The index lists the columns that identify one row. The first column is the event time and must be of type date or timestamp; the rest (a symbol, an issuer) must each declare a type. Knowledge time is added by MAYA — do not declare it.

{% call example('A daily price panel', 'json') %} "index": ["date", "symbol"], "index_types": {"date": "date", "symbol": "string"} {% endcall %} {% endcall %} {% call step(2, 'Schema: the value attributes') %}

Each attribute has a name and a logical type; a unit and a semantic tag are optional. At least one value attribute is required and names must be unique.

{{ fields([ ('int32 · int64 · float32 · float64', 'numbers'), ('bool · string · date · timestamp · duration', 'scalars; timestamps are stored in UTC'), ('decimal(p,s)', 'exact decimals'), ('list · fixed_vector · tensor · struct · map', 'nested values, for embeddings and curves'), ]) }} {% call example('Two attributes', 'json') %} "schema": [ {"name": "close", "type": "float64", "unit": "USD"}, {"name": "volume", "type": "int64"} ] {% endcall %} {% endcall %} {% call step(3, 'Source') %}

source.type is one of csv, parquet, json, sql, python, delta or derived. For uploads you may name a knowledge_time_column, a column in the file that says when each row became known; otherwise the upload instant is used. A python source is a sandboxed producer function; see SQL and Python sources.

{% call example('A CSV source with its own knowledge times', 'json') %} "source": {"type": "csv", "knowledge_time_column": "published_at"} {% endcall %} {% endcall %} {% call step(4, 'Resolution: grid and rules') %}

The grid is either as_is (the source's own rows) or a calendar — natural_days, ISO_business_days, NYSE, LSE or TARGET — crossed with every distinct non-date key. Then each attribute's rule fills the gaps, per symbol, in event-time order.

{{ fields([ ('none', 'leave gaps as null (the default)'), ('forward_fill(limit=3, max_age=5)', 'carry the last value, at most 3 periods and 5 days old'), ('backward_fill(limit=2)', 'take the next value — non-causal'), ('linear_interp(limit=2) · spline_interp(order=3)', 'interpolate — non-causal'), ('constant(v=0) · zero', 'a fixed value'), ('mean_of_window(n=5)', 'the mean of the previous n values'), ('last_known_as_of(lag=1)', 'the last value on or before the date minus lag days'), ('previous_period', 'the previous row\'s value, one period only'), ]) }} {% call example('Resolution on the NYSE calendar', 'json') %} "resolution": { "grid": {"calendar": "NYSE"}, "rules": {"close": "forward_fill(limit=3)", "volume": "zero"}, "default": "none" } {% endcall %} {% call warn('Non-causal rules look into the future') %}

backward_fill, linear_interp and spline_interp use values from after the gap. MAYA marks the version non-causal, and a training warrant refuses it unless someone records a justification.

{% endcall %} {% endcall %} {% call step(5, 'Transform and quality') %}

Transforms run in order: rename, cast, filter, derive, aggregate, pivot, unpivot, window, lag, resample, dedupe, clip, winsorize. Expressions use a restricted Python subset (arithmetic, comparisons, and/or/not, in, and functions such as abs, log, where, isnull, round, clip); anything else is refused by name.

{% call example('Transforms', 'json') %} "transform": [ {"op": "filter", "expr": "close > 0"}, {"op": "derive", "name": "log_close", "expr": "log(close)", "type": "float64"}, {"op": "lag", "attr": "close", "n": 1}, {"op": "window", "attr": "close", "fn": "mean", "size": 20} ] {% endcall %}

The quality contract runs on every resolution and always on pin; a failing check blocks the pin. Checks: not_null, unique_on_index, range, allowed_values, monotonic, max_daily_change, row_count_between, freshness_within.

A quality contract: see The whole definition at a glance in the full reference below.

{% endcall %} {% call step(6, 'Create, preview, submit') %}

Creating makes draft v1. Preview the draft against real data, then submit. Submitting validates the definition, type-checks a derivation, computes the definition hash and the change class against the previous version (breaking, behavioral or additive), and moves the version to in_review.

{% call example('The same thing from Python', 'python') %} import maya.sdk as maya my = maya.connect(base_url="http://localhost:8600", api_key="maya_…") definition = { "index": ["date", "symbol"], "index_types": {"date": "date", "symbol": "string"}, "schema": [{"name": "close", "type": "float64"}], "source": {"type": "csv"}, "resolution": {"grid": "as_is", "rules": {"close": "forward_fill(limit=3)"}}, "transform": [], "quality": [{"check": "not_null", "attr": "close"}], } my.features.create("eq", "prices", definition, description="Daily closes") my.features.ingest("eq/prices", open("prices.csv", "rb").read(), fmt="csv") print(my.features.draft_preview("eq/prices")["fill_report"]) my.features.transition("eq/prices", 1, "submit") {% endcall %} {% call tip('Cosmetic edits do not mint a version') %}

If a new draft hashes identically to the previous version, submit says “Nothing changed” instead of creating a duplicate. To change an approved feature, start a new draft from its page; the approved version is never edited.
