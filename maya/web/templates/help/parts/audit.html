{% from "help/_macros.html" import step, concept, tip, warn, example, fields, screen, cards %} {% call concept('A log nobody can quietly edit') %}

Every state-changing action in MAYA appends an entry to the audit log inside the same database transaction as the change itself, so a change without its entry cannot commit. Entries are hash-chained: each one's hash covers its content and the previous entry's hash, so altering or deleting any entry breaks every link after it. The table is append-only at the database level too — an update or delete is refused by a trigger.

That proves the log is internally consistent. It does not stop someone with direct database access from rewriting history and recomputing every hash after it: the result is consistent too. Custody anchors close that gap by pinning the chain head in places the database cannot reach.

What an entry holds

{{ fields([ ('seq', 'its position in the chain'), ('at / actor / principal_type / channel', 'when, who, and through which surface (web, api, sdk, scheduler…)'), ('action', 'what happened, for example access.granted, workspace.submitted, licence.refused'), ('object_type / object_ref', 'what it happened to'), ('detail', 'the specifics, as JSON'), ('request_id / ip', 'the W3C trace id of the request, and where it came from'), ('prev_hash / hash', 'the chain links'), ]) }} {% call step(1, 'Explore the log') %}

{{ screen('/admin/audit', 'Admin → Audit') }} searches actor, action and object, newest first. The explorer is for administrators and techops.

{% call example('Search the log from Python', 'python') %} import maya.sdk as maya my = maya.connect(base_url="https://maya.example.com", api_key="maya_prod_…") for e in my.admin.audit(action="licence.refused", limit=50): print(e["seq"], e["at"], e["actor"], e["object_ref"], e["detail"]) {% endcall %} {% endcall %} {% call step(2, 'Verify the chain') %}

Walking the chain recomputes every hash from the first entry and reports the first broken link, if any. The home page and System health show the result too.

{% call example('Verify the chain', 'python') %} print(my.admin.verify_audit()) # {'ok': True, 'checked': 18244, 'head': '9f3c…'} {% endcall %} {% call example('Or, with pin integrity, from the command line', 'bash') %} python -m maya.cli admin verify-integrity # 412 pin(s) checked; drift: 0; audit chain ok: True {% endcall %} {% endcall %} {% call step(3, 'Anchor the head outside the database') %}

Every hour the scheduler anchors the current chain head — its sequence number and hash — using each configured method. Administrators can also anchor on demand from {{ screen('/admin/custody', 'Admin → Custody') }}.

{{ fields([ ('signature', 'an Ed25519 signature over {seq, head, at}'), ('file', 'a JSON line appended to custody.anchor.file — point it at WORM or off-host storage'), ('event', 'an audit.anchored event, so every webhook subscriber holds a copy MAYA\'s administrators do not control'), ('rfc3161', 'a timestamp token from the authority at custody.anchor.tsa_url (off by default: it sends the head hash to a third party)'), ]) }} {% call example('config/application.yaml', 'yaml') %} custody: anchor: methods: "signature,file,event" file: "${MAYA_ANCHOR_FILE:}" # empty: /anchors.jsonl tsa_url: "${MAYA_TSA_URL:}" # required if methods names rfc3161 tsa_ca_file: "${MAYA_TSA_CA_FILE:}" # the TSA's CA (PEM): its signature is checked interval_seconds: 3600 {% endcall %} {% call example('Anchor now, and list anchors', 'python') %} row = my.custody.anchor() print(row["seq"], row["head_hash"], row["methods"]) print(my.custody.anchors()["anchors"][:3]) {% endcall %} {% endcall %} {% call step(4, 'Verify the anchors') %}

Verification checks each anchor against the live chain: is the hash it pinned still the hash at that sequence number, does its signature verify, is it still in the anchor file, and — for a timestamp token — does the token carry this head's imprint and, with custody.anchor.tsa_ca_file set, does the authority's signature chain to that CA.

{% call example('Verify chain and anchors', 'bash') %} curl https://maya.example.com/api/v1/custody/verify -H "Authorization: Bearer $MAYA_API_KEY" {% endcall %} {% call example('A rewritten history, caught', 'json') %} { "ok": false, "verdict": "TAMPERING: 2 anchor(s) contradict the chain", "chain": {"ok": true, "checked": 18244, "head": "…"}, "broken": [{"seq": 17006, "problems": [ "the live chain no longer has this head at this position: history before it was rewritten"]}] } {% endcall %}

Note chain.ok is true: the chain alone was fooled. The anchors were not.

{% endcall %} {% call warn('An anchor is only as external as you make it') %}

On the same disk as the database, the anchor file only raises the bar. Put it on write-once or off-host storage, subscribe an independent system to audit.anchored webhooks, or enable RFC 3161. MAYA checks a timestamp token's status and imprint; it checks the authority's own signature only when custody.anchor.tsa_ca_file names the authority's CA certificate (through openssl ts -verify, which must be installed — MAYA refuses to start otherwise). Without it, run that command yourself: an unchecked signature is the authority's claim, not evidence.
