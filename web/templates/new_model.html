THE REGISTER

Create a model, or upload a version

A model is a parametric kernel, f : P × X → D(Y). Registering one declares the kernel; uploading a version declares what will actually run. An execution engine that has just finished a fit uses the same two endpoints.

1 — Register the model
Assess the risk tier next. The tier decides how many signatures a version's approval needs, so a version cannot be approved before the model is assessed — approving first would be choosing your own control depth.

Or put the file in MAYA stored under its own sha256; up to 8 GiB
A digest with no location cannot be fetched; a location with no digest cannot be checked. Supply neither and the version is descriptor_only: MAYA holds the governance and the engine supplies the model — a legitimate state, and one the warrant says out loud rather than guessing around.
From an execution engine

The same two endpoints. An engine that has just fitted a model registers the version and then records the parameters against the warrant it fitted under:

POST /api/v1/models                      # once, when the model first exists
POST /api/v1/models/{name}/versions      # the kernel that will run
POST /api/v1/parameters                  # the inhabitant of P it produced
     {"warrant_id": "…", "featureset": "…", "featureset_version": 1, …}

The parameters are accepted only against a warrant MAYA issued, and only when they name the featureset version that produced them. Somebody other than the engine's operator approves them before anything runs on them.
