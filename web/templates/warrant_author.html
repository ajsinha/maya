THE BOUNDARY

Warrants

A warrant is a signed, expiring, entitlement-bound contract authorising one act, on one model version, by one principal, for one stated use. MAYA issues it; an execution engine acts on it. That separation is why a governed version move never requires a consumer to redeploy — the consumer holds a URN and everything else is resolved at the moment of use, against the policy in force at that moment.

Nothing on this page decides anything. Every button posts to the same endpoint an external engine calls, and every refusal below is the platform's answer rendered verbatim, with the remediation it supplied.

1 — The standing grant

A grant is the standing entitlement: this principal, in this environment, for this declared use. A descriptor is the short-lived credential minted against one. Separating them is what makes revocation meaningful — withdrawing the grant stops future descriptors, and bumping the epoch invalidates the ones already out.

Nothing resolves without one. A resolution for a principal that holds no grant is refused no_entitlement with a 403, and that refusal surprises almost everybody the first time. It is not a bug and it is not a permission problem with your login: it means nobody has yet said that this principal may use this model in this environment for this purpose.

2 — Profiles: templating the request, never the warrant

"Warrants should be templated by kind of model" is half right, and the wrong half is expensive. The document must not fork: one grammar over every model family, with no engine branching on model type before it can read anything. What is genuinely tedious is the request — the same verb, the same ceiling, the same binding shape retyped for every warrant of a kind. A profile fills that in, and nothing else.

3 — Resolve a scoring warrant

The hot path. A signed descriptor, or a refusal with a reason. The order of the checks is the part that has to be right: the model must not be blocked by an open finding, then the principal must hold a grant, then the grant must not have been withdrawn, then the declared use must match the approved one, then the version the alias points at must be approved.

The verb list is the grammar's, not this page's. The other verbs are still offered, so that a refusal explains itself rather than a control silently disappearing.

4 — Fit → parameters → score, the whole round trip

Fitting does not change the kernel. f : P × X → D(Y) stays as it was; a fit picks a point in P. So a fit produces a parameter set, not a version — and the round trip is: MAYA issues a fit warrant, an engine trains somewhere else, the numbers come back naming the warrant that produced them, and somebody who is not their author approves them before anything runs on them.

The id that goes back is the grant's, not the descriptor's. A resolved descriptor is minted per request and never stored, so its warrant_id is not something MAYA can vouch for later. What is persisted is the standing grant, so that is what POST /parameters checks its warrant_id against. Quoting the descriptor's id is refused unknown_warrant. The forms below carry the grant's.

5 — Revocation, grace and the epoch
A revocation
withdraws the grant, so no further descriptor is minted against it, and bumps the epoch
The epoch
currently {{ epoch }}. Every descriptor carries the epoch it was minted under, so an engine can tell a stale credential from a current one
Grace extends
how long a descriptor's authorisation stays current when the platform is unreachable
Grace does not extend
how long a consumer may stay ignorant of a withdrawal it has already been told about. That is the revocation floor, and grace never overrides it

The captive engine keeps a local revocation list, and a descriptor naming anything on it is refused revoked with "stop; grace never extends revocation ignorance" — before the expiry check, and before an artifact is touched.

{{ curl.revoke }}
This is the kill switch and it is the only revocation the HTTP API offers: it withdraws every grant on the model, in every environment, for every principal. There is no endpoint for withdrawing one grant, though the service underneath has the method.
6 — The operating boundary, and violations of it

The operating contract travels inside the warrant, in constraints: the assumptions the model was built under, the guarantees it makes while they hold, and what an engine should do when an input falls outside. MAYA does not check inputs — it never sees them — so a violation is reported by whatever ran the model, against the boundary the warrant carried.

7 — The fourteen admissibility laws

A warrant can be well-formed and still be nonsense: asking a closed form to be fitted, training on a source that cannot be read as-of, generating text from a gradient-boosting model. These are the rules that make such a document a refusal rather than a runtime failure — and the validator reports every problem rather than stopping at the first, because fixing one error to be told about the next is the worst possible interface for a document with ten sections.
