Evidence integrity

Two questions, and they are not the same question. The chain can be checked against itself, which tells you nothing has been edited carelessly — but a chain rewritten from the first node onwards passes that check perfectly. The anchors are heads copied to write-once storage outside the database; comparing against them is the only check here that somebody holding the database cannot simply satisfy.

A token bounds a head from above only: it proves this hash existed no later than that time, which is what stops a chain being written after the fact and dated before it. It says nothing about how early the head existed, nothing about whether anything was deleted, and nothing at all about the period before the first token was taken. unverified is a third state on purpose — a token nobody can check is not the same as no token, and it is not the same as a verified one.
