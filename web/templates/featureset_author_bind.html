Sealed — it takes no further versions
Sealing is what makes a featureset final. It does not make it inert: a sealed set can still be composed from, still assembled from, and still named by a warrant — that is what sealing is for. What it forbids is another version and a change of policy, so that a child which composed against it cannot have the ground move. Breaking a seal needs principal:manage and is recorded as an act, never quietly.

Bind each slot — one feature, one pinned view version
Leaving the view blank asks the register to find the one view carrying that feature and take its newest version. Where two views carry it the binding is refused rather than guessed at, and the refusal names them — guessing here is how a set silently reads the wrong bytes. Naming a view without a version is refused for the same reason: a version that did not pin exactly would resolve to different bytes next month with its digest unchanged.
