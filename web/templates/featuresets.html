Featuresets

A featureset declares a schema — named slots with types — and a version fills it, binding each slot to a feature and to the exact feature view version supplying its values. Two versions may hold entirely different features and still be the same input space, because the kernel reads the slot.

Compose a featureset Compare two schemas

Declare a featureset

1 · Slots it declares itself

The slots are the schema, and the schema is what a kernel is defined over. Adding one later changes X, which is a model change rather than a data change — so it becomes a different featureset and the register says so instead of letting it happen quietly.

2 · Featuresets it composes from

A combination of featuresets is a featureset. Order matters and is left to right, rightmost wins — the leftmost parent is the least prominent. A child inherits its parents' slots and their retrieval policy, and the version it composed against is recorded, so a parent that moves afterwards is reported as drift rather than changing the child silently.

3 · What it changes about what it inherited

add a slot the parents do not have, drop one they do, or override one with a different type. Every operation is total: adding a slot that already exists, or dropping one that does not, is refused rather than quietly doing nothing — because an operation that silently does nothing is one somebody believes happened.

4 · Lifetime and default retrieval

Attached as this featureset's default behaviour; a request may still override it column by column, and a child inherits it and may override part — the same fold, with the rightmost winning.
