{# The formats are listed in the order somebody actually has one. CSV and JSONL are what a person brings; the page named neither and led with Parquet, so the format the tutorials use looked unsupported. The `accept` attribute above has always taken them — the prose was the part that was wrong. #} CSV or JSONL for a file somebody has; Parquet or Arrow IPC when it is coming from a job. A CSV is read and never written: it cannot carry a type, so a feature exported as one would come back as text with both clocks as strings. Every row carries entity_id, event_ts (when the fact was true) and ingest_ts (when we learned it) — a row without both clocks is refused here rather than two layers later, where it stops being fixable. Nothing is held whole: the upload is parsed a batch at a time.
{# ------------------------------------------------------ where values come from Two ways in, and the screen has to offer both. Somebody uploads a file, or MAYA pulls from where the data already lives — a warehouse query, a file on a volume, an object in a store. MAYA PULLS; it does not read through. What it fetches is written into its own Delta as a new version, so integrity, versioning and the two clocks stay MAYA's. Serving a model straight off a warehouse table would give away point-in-time correctness: a table overwritten since March cannot say what was knowable in March, and it would answer something rather than refuse. #}
