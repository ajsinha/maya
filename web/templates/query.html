Query the register

Every governance platform is eventually asked for database access so the BI team can build their own dashboards. Granting it is the fastest way to lose the register — and it never looks like a failure while it is happening.

A tool pointed at the physical schema has to decide for itself what in force means. status = 'approved' is the obvious answer and it is wrong: a model can be approved and carry a blocking finding, an expired attestation, a lapsed warrant. So a second definition of the most important word in the register comes into existence, lives in a dashboard nobody governs, disagrees with the platform — and is the one on the slide. Handing out SQL is not a semantic layer; it is a database credential with a nicer name.
This layer publishes entities and fields, never tables and columns. Every field marked derived is computed by the same code the screens use. There is no box on this page that takes query text, and there is no parameter for one.

Saved views
A saved view holds the query and never the rows. An author whose scope reaches four legal entities shares a view; a reader scoped to one opens it — and if the rows had been stored, that reader would now hold three entities' worth of models because somebody clicked share. Storing the query means the view re-runs under whoever opens it, so two people running the same view legitimately see different numbers.
