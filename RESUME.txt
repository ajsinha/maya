THE LOOP, PER BATCH
-------------------
  1. Read the batch's rows in qa/ACTION-PLAN.md.
  2. Fix at the SERVICE, not the route. A body model can only refuse a field
     that is ABSENT; "   " is present and satisfies it.
  3. A new refusal code needs an entry in routes/base.py::STATUS, or the
     discipline test fails the build.
  4. A platform fix gets a unit test in tests/ saying what was wrong.
  5. Re-run the SECTION, not the case. A verdict from a single-case run has
     been wrong in both directions.
  6. Run gates.sh and the full suite. Both green.
  7. Update qa/ACTION-PLAN.md: move the batch into a "closed" section that
     says what it FOUND, and drop the rows that now pass.
  8. Drill: commit on develop -> push develop -> checkout main -> merge
     develop -> push main -> checkout develop.

Re-run before writing the summary. Batch B was written up as closed with one
of its findings still failing, because the summary was assembled from what had
been fixed rather than from what was still failing.
